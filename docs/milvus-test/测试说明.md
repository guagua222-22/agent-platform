# Milvus 知识库测试说明

只将同目录的《星舟公司内部手册.md》导入知识库。本说明包含测试答案，不要入库。所有事实均为虚构，尤其适合判断 Agent 是否真正使用检索证据。

## 导入方式

当前项目入库接口接收 JSON 的 title 和 content，不直接接收附件。可在项目根目录使用 PowerShell 执行下列命令；将 BaseUrl 改成实际服务地址。执行会新增一份知识库文档，并调用项目配置的 embedding 服务；重复执行会重复入库。

```powershell
$BaseUrl = 'http://localhost:8080'
$DocPath = Join-Path (Get-Location) 'docs/milvus-test/星舟公司内部手册.md'
$Content = Get-Content -LiteralPath $DocPath -Raw -Encoding UTF8
$Payload = @{ title = '星舟公司内部手册 XZ-2026-R4'; content = $Content } | ConvertTo-Json -Compress
$BodyBytes = [System.Text.Encoding]::UTF8.GetBytes($Payload)
Invoke-RestMethod -Method Post -Uri "$BaseUrl/api/knowledge/docs" -ContentType 'application/json; charset=utf-8' -Body $BodyBytes
```

成功响应应含 docId、大于 1 的 chunkCount 和 READY 状态。项目目前使用 500 字符分块上限、50 字符重叠；KB 编号是手册条目编号，不等于实际分块 seq。一条内容可能落入多个分块。

单条查询示例：

```powershell
$Query = [Uri]::EscapeDataString('灯塔演练集合时的核验暗号是什么？')
Invoke-RestMethod -Method Get -Uri "$BaseUrl/api/knowledge/search?q=$Query&topK=5" | ConvertTo-Json -Depth 6
```

## 怎么判断效果

1. 先用 T13 验证入库与召回：返回 content 应包含独有暗号，docTitle 应为刚导入的手册标题。再看 chunkId、seq 和 score 是否有值。
2. 对单条目问题，将 topK 分别设为 1 和 5，观察目标证据是否在第一条或前五条。对比 T09/T10、T19，检查相似内容是否被混淆。
3. 对 T04、T17、T20 使用 topK=5，检查返回内容是否覆盖问题需要的两部分。仅命中其中一部分时，Agent 没有足够证据完成比较。
4. Agent 回答 T21/T22 时，应承认缺少信息。当前检索接口没有相关度拒答阈值，无答案问题仍可能返回结果；返回若干片段本身不代表存在答案。
5. 记录每题目标事实是否进入前五条，用“命中题数 / 可回答题数”计算简单的事实召回率；T21/T22 单独检查拒答，T23 检查错误前提纠正。不要用一个固定 score 数值替代内容核对。

这套文档主要验证文档切分、向量入库、语义召回、返回来源和 Agent 使用证据的能力。它不是性能压测数据，也不覆盖当前 API 未提供的删除、元数据过滤或混合检索功能。本文档尚未提交到运行中的服务，检索效果需导入后实际确认。
